# Security review, 2026-11-25

A pass over the whole app as of `fd95781` (`main`, 2026-11-21): the Electron setup, what the page can ask of main and the core, every place a program is started, secrets, dependencies, and updates. README.md, RESTORE.md and the CHANGELOG's security entries were read first; there were no earlier notes in `docs/security`. What those already accept is not repeated here: unsigned packages that open the release page instead of installing themselves, a checkout that updates from its upstream branch, `core.fsmonitor` switched off for automatic git work, the 16 MiB cap on git output, CI on hosted runners with pinned actions.

The page is treated as untrusted throughout. It shows file names, commit messages and diffs from repositories nobody has vetted, so the question for each interface was: what could the page do with it if its script were someone else's?

## What was checked

| Area | Result |
| --- | --- |
| Electron hardening | `sandbox`, `contextIsolation` and `nodeIntegration: false` are set; `webSecurity`, `webviewTag` and drag-and-drop navigation are at their safe defaults; navigation away from the page and new windows are refused. Fixed: the page check, `shell.openPath`, the missing content security policy, loading from `file:`, the permission handlers. |
| What the page can ask (preload bridge, IPC, the core's API) | The bridge hands over one `call(method, args)` to the core and seven named calls to main; no raw IPC, `fs` or `exec`. Fixed: method lookup, argument checks, paths outside the repository, folders the user never chose. |
| Starting programs | git, `gh`, VS Code and the system tools (`lsof`, `ss`, `where`) are started with an argument list, never a command string. A shell is started in three places, each with a fixed script and anything variable passed as an argument. Fixed: commit hashes and branch names that git would read as options. |
| Secrets | `git log -p --all` searched for token and key patterns and for key and `.env` file names: nothing. Packages hold `out/**` without source maps, `package.json` and two icons. |
| Dependencies | `pnpm audit --prod` and `pnpm audit`: no known vulnerabilities. Every version is pinned exactly, so there is no range to move inside. Two newer patch and minor versions exist (`@tanstack/react-virtual` 3.14.28, `lucide-react` 1.79.0) and are left to the weekly refresh; `@types/node` stays on 24 on purpose. |
| Updates and `install.sh` | Packaged builds ask GitHub Releases over HTTPS and open the release page; they install nothing. `install.sh` downloads nothing. Both workflows pin their actions by commit and ask for the least permissions. |

## What was fixed

Each has regression tests next to the existing ones (`test/`, and `e2e/app.spec.ts` where it takes the running app).

| Commit | Problem | Now |
| --- | --- | --- |
| `a3c342c` | A "commit hash" such as `--output=/some/file` made git write that file; a branch name such as `--orphan=x` was read as an option. | Hashes are hex only; a branch name can't start with `-` or hold control characters. |
| `ac7607c` | The RPC layer looked a method up on a plain object, so `constructor` or `__proto__` counted as methods. | Only registered handlers are called. |
| `1d6768c` | Compare and Discard followed a path git reported through a linked folder, out of the repository. | Every such path is resolved first and must stay inside the working tree. |
| `b540e94` | The core took arguments as they came: any settings key (`__proto__` included), any type. | Every method checks its arguments; settings are a fixed list with typed values. |
| `53ec6c2` | The page could add any folder to the deck, or switch on a folder's "Show New Projects Automatically", and so set git to work where the user never pointed. | Main keeps what the user chose (the dialog, a real drop, the command line), once and for a minute; switching on the watch asks in a system dialog. |
| `fb2b87b` | Main took any `file:` page for its own, opened any existing path (a program, on some systems) and any folder in VS Code. | Only the top frame of RepoDeck's page is answered; only deck folders and the settings folder are shown; only parsed `http(s)` links go to the system; every permission request is refused. |
| `a0a5eaa` | A remote whose address merely contains `github.com/owner/name` was shown that project's pull requests and CI. | The host must be github.com, in the forms git, curl and ssh read alike. |
| `d640a67` | The cache and the activity log were readable by every account, and written through whatever stood at their path. | Mode `0600` from the first byte, replaced rather than rewritten, never through a link, pipe or second name. |
| `b1bd241` | Loaded from `file:`, the page could load any script on the disk as its own. | Main serves the built page at `repodeck://app`, from its own folder only. |
| `aa4c029` | No content security policy. | Own scripts, styles and images only; nothing inline or evaluated; no network. |

## What was left, and why

- **Signing and update integrity.** Packages are unsigned and a checkout trusts its upstream. Already accepted in the README; fixing it means certificates and keys, which is the owner's decision. Electron fuses (no `ELECTRON_RUN_AS_NODE`, no `--inspect`, asar integrity) belong with it: they change every packaged build and want a signed one to be worth much.
- **macOS and Windows were not run.** Everything was tested on Linux, including a packaged build loading from `app.asar`. `b1bd241` changes how every build loads its page and `fb2b87b` has macOS- and Windows-only branches; start a packaged build on both before this is released.
- **A repository's own git configuration.** Hooks, filters and `core.sshCommand` in a repository run when git works there. That is git; the guard is that only folders the user chose join the deck.
- **A program rewriting a working tree while RepoDeck uses it.** Paths are checked, then used; a folder swapped for a link in between is followed. Git has the same gap, Node has no way to open a file relative to a checked folder, and the Trash takes a path.
- **Privacy of the cache and log where the file system has no modes.** On Windows they are as private as the profile folder they sit in; on a network or removable drive that ignores modes, as private as the mount. Refusing to keep them there would break both without saying why.
- **Two RepoDecks on one profile.** One runs per profile (main holds the lock). Two cores started by hand on Windows could each write the first line of a new log, and one would win.
- **`--no-sandbox` when run as root** (the Linux launcher): Chromium refuses to sandbox root; don't run it as root.
- **`RESTORE.md`** names the machines and backup paths behind this project, in a public repository. Whether it belongs here is the owner's call.
- **Smaller things**: `install.sh` and the Linux autostart entry write an `Exec=` line with the path unquoted (breaks, rather than misleads, with a space in it); the autostart entry of a packaged build points at `bin/repodeck`, which only a checkout has.

## How it was verified

`pnpm test`, `pnpm typecheck` (the repository's lint), `pnpm build` and the Playwright suite under Xvfb, all green on Linux. The tests for a folder that takes no new file were also run without root's write-anywhere privilege, as CI runs them. A packaged build (`electron-builder --dir`) was started to see the page load from `app.asar` at its own address with nothing refused by the policy.
